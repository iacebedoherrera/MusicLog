# Implementation Plan: Health Endpoint

**Branch**: `feature/health-endpoint-spec-kit` | **Date**: 2026-08-08 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/002-health-endpoint/spec.md`

## Summary

Add the protected `GET /health` contract that returns exactly `{"status":"UP"}` with HTTP 200 for an authenticated request. Implement it as a request-local web concern in the existing `shared.web` boundary: obtain the authenticated user through `AuthenticatedUser` without exposing or using its data in the response, and use a typed one-field response with no service, persistence, event, external integration, or security-configuration change. Keep the OpenAPI documentation generated by the backend and the frontend API-contract documentation synchronized. Verify the route, its JWT policy, authenticated `POST /health` returning HTTP 405 without the success body, the exact body, and the generated OpenAPI through focused HTTP integration tests.

## Technical Context

**Language/Version**: Java 21

**Primary Dependencies**: Spring Boot 3.3.5, Spring MVC, Spring Security with JWT, Spring Modulith; use existing test support only

**Storage**: N/A — the endpoint creates and persists no data

**Testing**: JUnit 5, Spring Boot integration test, MockMvc, existing JWT service/test profile, generated OpenAPI document assertions, and frontend quality commands after the documentation-only contract update

**Target Platform**: HTTP endpoint served by the existing backend

**Project Type**: Modular web service

**Performance Goals**: No new throughput or latency target; the response is a fixed, request-local availability signal with no new I/O

**Constraints**: Exact successful JSON body `{"status":"UP"}`; HTTP 200 only for an authenticated request; the protected controller obtains `AuthenticatedUser` through the established mechanism but does not expose identity data; authenticated `POST /health` returns HTTP 405 and never the health success body; preserve `SecurityConfig`; document the protected route and a closed response schema in both generated OpenAPI and `frontend/docs/api-contract.md`; do not modify persistence, Flyway, Redis, Docker, CI/CD, infrastructure, dependencies, external integrations, or frontend runtime code; expose no diagnostics or sensitive information

**Scale/Scope**: One additive endpoint, one response type, focused HTTP/OpenAPI integration coverage in `shared`, and one frontend API-contract documentation update; no persistence, events, jobs, or frontend runtime work
